  Key design decisions

  - Models are volume-mounted, not baked in — your existing ~500GB models/ directory is shared directly into the
  container via .env
  - Custom nodes persist in a named Docker volume (comfyui_custom_nodes), so anything you install via Manager survives
  container rebuilds
  - ComfyUI-Manager is auto-installed on first run (not baked into the image), so it lives in the persistent
  custom_nodes volume and can update itself
  - All versions are parameterized via build args (CUDA_VERSION, TORCH_CUDA, COMFYUI_REF) — you can pin to a specific
  ComfyUI tag or bump CUDA without editing the Dockerfile
  - CMD is overridable — add flags like --highvram, --fp16-vae, etc. via the commented-out command: line in
  docker-compose

  Usage

  cd C:/Stable_Diffusion/ComfyUI_windows_portable/comfyui-docker

  # Build and start
  docker compose up --build -d

  # View logs
  docker compose logs -f

  # Stop
  docker compose down

  # Rebuild with a different ComfyUI version or CUDA stack
  docker compose build --build-arg COMFYUI_REF=v0.13.0 --build-arg TORCH_CUDA=cu126

  Then open http://localhost:8188 — Manager will be ready on the first boot for you to install any additional custom
  nodes you want from the inventory.
